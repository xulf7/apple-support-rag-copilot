# 架构与写作说明

本文给报告和展示材料的撰写者阅读，不要求先懂代码。当前进度见
[任务与进度](MVP_PLAN_AND_TASKS.md)，操作步骤见[资料与运行指南](DATA_PREPARATION.md)。

## 1. 项目解决什么问题

客服处理问题时，需要查找适用资料、保留操作条件，并说明建议的依据。
本项目把“找资料”和“草拟回复”接起来，减少反复查阅的工作，并让客服能回到原文核对。

使用者是内部客服人员。系统输出供客服审核的建议，最终由客服决定如何回复客户。

## 2. RAG 是怎样工作的

RAG 可以理解为“先检索资料，再根据资料生成”。资料准备和客服提问分成两个阶段：

```mermaid
flowchart LR
    A[官方支持文章] --> B[保存与清洗]
    B --> C[切块并建立本地向量索引]
    Q[客服输入问题] --> R[检索相关片段]
    C --> R
    R --> L[生成建议正文与引用 ID]
    L --> V[校验引用并绑定真实来源]
    V --> W[网页展示建议和证据]
    W --> H[客服核对后回复客户]
```

图中生成环节的接口已实现，真实 LLM 服务仍待接入。当前网页能展示检索证据，
但会明确提示生成未配置，不提供模拟客服回复。

- **资料准备**：保存允许访问的官方页面，保留小标题、步骤、条件和链接，去除导航及反馈组件。
- **建立索引**：把长文章切成片段，再把片段转成表示语义的数字向量，便于查找。
- **提问检索**：把问题也转成向量，用 FAISS 找相似片段。
- **生成与审核**：把问题和选中的证据交给 LLM；后端检查引用并展示出处，客服再核对正文。

“相似”表示检索相关性，不表示答案正确的概率。

## 3. 为什么采用这些设计

| 设计 | 对项目的作用 |
|---|---|
| 使用官方来源并保留 URL、版本和片段位置 | 能追溯建议所依据的原文 |
| 本地英语 MiniLM 模型和 FAISS | 目前无需付费 embedding API，适合小规模资料库 |
| 按标题、段落和步骤切块 | 尽量保留操作顺序、前提和解释 |
| 同一 Flask 应用提供网页与接口 | 部署简单，检索、生成和网页仍分开维护 |
| 模型与索引启动时加载、请求间复用 | 避免每次提问重新加载资源 |
| 一次生成，统一展示建议正文 | 回答、限制、条件和建议确认的信息都能自然表达 |
| 客服人工审核 | 给最终回复保留人工判断环节 |

当前模型输出 384 维向量，6 篇文章形成 56 个片段。切块预算为 240 tokens，
模型上限为 256；计算包含标题和章节，避免静默截断。token 是模型计量文本长度的单位。

## 4. 各部分分别负责什么

| 部分 | 职责 | 主要文件 |
|---|---|---|
| 导入与检查 | 识别官方来源、清洗正文、保留原文及版本、检查完整性 | `src/ingest.py`、`src/import_saved.py`、`src/check_corpus.py` |
| 切块与检索 | 编码文本、建立及重载索引、返回相关片段 | `src/embedding.py`、`src/retrieval.py` |
| 流程协调 | 接收问题、选择上下文、调用生成器、映射引用和处理工程异常 | `src/service.py` |
| 生成接口 | 提示词、建议正文与引用 ID 的格式校验、超时和忙碌处理 | `src/generation.py` |
| 网页 | 问题输入、状态、建议正文、真实来源和可展开证据 | `src/web.py`、`src/templates/`、`src/static/` |

新增资料经导入、审核、显式重建索引和重启后即可参与检索，无须修改固定主题路由。

## 5. 生成结果与来源怎样关联

生成器只需返回建议正文 `suggested_response` 和引用列表 `citation_ids`。
提示词要求依据本次证据，保留适用条件、设备分支、例外和限制；资料只支持一部分时，
给出有依据的部分，并在同一正文说明未覆盖之处或需要确认的信息。

后端为本次实际选中的片段分配 E1、E2 等引用 ID，再映射到文章标题、URL、
章节、文档版本和片段位置。网页分别展示检索候选、已提交的上下文及回复实际引用的来源。

引用列表允许为空，例如模型说明没有依据。未知、重复或与正文标记不一致的引用会被拒绝。
引用绑定通过只能说明出处映射有效，不能自动证明每个结论都被资料支持。

## 6. 已有验证结果及写作边界

以下是截至 2026-10-25 的开发验证摘要。组员可直接理解和引用这些范围，
原始日志由维护者保存在本机，无需从 GitHub 下载隐藏附件。

| 验证对象 | 已执行结果 | 能说明什么 |
|---|---|---|
| 六篇真实资料 | 完整性和结构检查 6/6，通过 AI 内容审查；另已人工核对修改密码整页 | 当前版本可继续开发，其余五篇未宣称人工全文审核 |
| 真实本地检索 | 35 次查询中，21 条有文档标签均首名命中 | 小型开发集的文档检索表现，不是答案正确率或盲测结果 |
| 未配置生成器 | 35 次均保留真实证据，返回生成未配置 | 未用假回复代替真实 LLM |
| 自动回归 | 65 项 Python、5 项前端逻辑测试通过 | 合成资料下的流程、引用、安全与异常处理有效 |
| 解析兼容性 | 两组 BeautifulSoup/SoupSieve 组合通过测试及六篇结构检查 | 已验证的解析组合可处理当前资料 |

真实 LLM 的回答正确性、有据性、资料不足时的表现，以及浏览器实际使用体验仍待验收。

真实生成示例、回答质量指标和最终界面截图，等对应功能验收后再补。
不要把预期效果或合成测试结果写成真实 LLM 已达到的成果。
